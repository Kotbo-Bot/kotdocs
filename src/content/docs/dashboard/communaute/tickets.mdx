<p class="doc-lead">Le module <strong>Tickets</strong> permet à vos membres d'ouvrir un espace d'échange privé (salon, fil ou message privé relayé) avec votre équipe. Depuis le dashboard, le staff les traite comme dans un outil de support : files, priorités, attribution, objectifs de délai et statistiques.</p>

:::tip[Côté Discord]
Pour voir comment se présente le panneau, comment les membres ouvrent un ticket et comment le staff y répond sur Discord, consultez le [guide Discord des tickets](/discord/communaute/tickets).
:::

:::note[Où la trouver]
Section **Équipe → Tickets** : [Ouvrir les tickets ↗](https://dash.kotbo.fr/tickets).
Les onglets de gestion et de configuration sont réservés aux administrateurs et aux rôles d'accès configurés.
:::

La page compte sept onglets : **Tickets**, **Performance**, **Transcriptions**, **Satisfaction**, **Réponses types**, **Liste noire** et **Configuration**.

## Traiter les tickets (onglet Tickets)

### Les files

À gauche, les tickets sont rangés en **files**, chacune avec son compteur :

| File | Contenu |
| --- | --- |
| **À traiter** | Les tickets où le membre attend une réponse du staff. |
| **En cours** | Tous les tickets ouverts. |
| **Non attribués** | Les tickets ouverts sans personne attitrée. |
| **Mes tickets** | Ceux qui vous sont attribués. |
| **Hors délai** | Ceux qui ont dépassé un [objectif de service](#objectifs-de-service). |
| **À valider** | Les demandes en attente de validation, quand la validation préalable est activée. |
| **Fermés** et **Tous** | L'historique. |

Le champ **Rechercher un ticket** accepte un membre, une raison, une `#étiquette` ou un identifiant. Le tri bascule entre **Plus anciens d'abord** et **Plus récents d'abord**, et les touches `j` / `k` passent d'un ticket à l'autre.

Dans la liste, chaque ticket signale s'il est **En attente d'une réponse du staff** ou **En attente du membre**, sa priorité quand elle est **Haute** ou **Urgente**, et à qui il est attribué.

### La conversation

Au centre s'affichent les messages du ticket. Le champ **Écrire un message…** répond directement : le message part dans le salon Discord du ticket, au nom du compte staff connecté.

Quand [AegisAI](/dashboard/moderation/aegis/) analyse l'humeur des tickets, l'humeur du demandeur s'affiche sur chaque ticket.

### Les propriétés

À droite, le bloc des propriétés règle :

* la **Priorité** : **Basse**, **Normale**, **Haute** ou **Urgente** ;
* **Attribué à** : un membre du staff (la liste indique combien de tickets chacun a déjà en cours), ou **Personne** ;
* les **Étiquettes**, pour classer les tickets et les retrouver dans la recherche ;
* les **Objectifs** : le temps restant avant l'échéance de **1re réponse** et de **Résolution**, ou leur dépassement.

En dessous, la fiche du membre résume son ancienneté, ses rôles, son **Casier** (avertissements, sourdines, exclusions, bans), ses tickets passés et leur note moyenne, et une **Note du staff**. **Dossier détaillé** ouvre son dossier sans quitter la page, où une sanction peut être appliquée ; **Fiche complète** ouvre sa [fiche membre](/dashboard/moderation/membres/).

### Les actions

| Action | Effet |
| --- | --- |
| **S'assigner** | Vous attribue le ticket. Le bot l'annonce dans le salon. |
| **Sur-revendiquer** | Reprend un ticket déjà attribué à quelqu'un d'autre, si la configuration l'autorise. |
| **Fermer** | Ferme le ticket. Une **Raison de la fermeture** peut être ajoutée, elle est facultative. |
| **Réouvrir** | Rouvre un ticket fermé. |
| **Archiver** / **Désarchiver** | Un ticket archivé **garde son salon**, qui passe en lecture seule. |
| **Verrouiller** / **Déverrouiller** | Protège le ticket contre la suppression (voir ci-dessous). |
| **Renommer** | Change le nom du salon Discord. |
| **Restaurer** | Recrée le salon d'un ticket supprimé, avec tout l'historique des messages, noms et avatars d'origine. Trois restaurations au plus par ticket ; les pièces jointes d'origine ne sont pas restaurées. |
| **Supprimer** | Supprime le salon sur Discord et génère une transcription. |

### Protéger un ticket contre la suppression

**Verrouiller** ouvre **Protéger contre la suppression** : tant que la protection est active, le ticket ne peut être supprimé ni depuis le dashboard ni depuis Discord. Choisissez une **Durée de la protection** (*7 jours*, *30 jours*, *90 jours* ou *Sans échéance*) et un **Motif** facultatif.

Le ticket affiche alors **Protégé contre la suppression**, avec l'auteur et l'échéance du verrou.

### Valider une demande

Avec la validation préalable, une demande n'ouvre aucun salon tant qu'elle n'est pas acceptée. Elle apparaît dans la file **À valider** :

* **Valider la demande** crée le ticket ;
* **Refuser** demande un **Motif communiqué au membre**, qui reçoit le refus en message privé.

La même décision peut se prendre depuis la carte publiée dans le salon de validation sur Discord.

## Mesurer le support (onglet Performance)

L'onglet donne les délais du support en **médiane**, avec le 90e centile pour repérer les tickets oubliés, sur la **Période** choisie. **Comparer à la période d'avant** superpose la période précédente.

* Le bloc **En cours** compte les tickets sans personne attitrée et ceux qui attendent une réponse du staff.
* **Par membre du staff** : tickets pris en charge, délais médians et satisfaction de chacun.
* **Par type** et **Par étiquette** : où se concentrent les demandes.
* **Notes reçues** : la répartition des notes de satisfaction.

## Transcriptions (onglet Transcriptions)

L'onglet reprend l'ancienne page **Transcriptions**, dont l'adresse `/transcripts-list` mène désormais ici. Il liste les transcriptions de **tickets** et de **salons** :

* un ticket est transcrit quand on le **supprime**, et de nouveau quand on l'**archive**, pour que l'archive reflète son dernier état ;
* la commande `/transcript` et l'import de messages comme preuves dans un [rapport de sanction](/dashboard/moderation/sanctions/) produisent les transcriptions de salons.

La colonne **Type** distingue les deux : **Ticket** ou `/transcript`. **Consulter** ouvre la transcription complète dans un nouvel onglet.

La suppression est réservée à qui gère les réglages du serveur. Une confirmation la précède : la transcription disparaît du tableau de bord et son lien ne marchera plus.

:::danger[Suppression définitive]
Une transcription supprimée n'est pas récupérable. Si elle sert de preuve dans un rapport de sanction, le rapport perd sa pièce jointe.
:::

## Suivi de la qualité (onglet Satisfaction)

À la fermeture d'un ticket, le bot demande au membre de noter le support reçu, de 1 à 5 étoiles. L'onglet **Satisfaction** affiche :

* la note moyenne et la répartition des notes ;
* la **Satisfaction par staff** ;
* les **Avis récents**, avec un filtre **Avec commentaire**.

La question de commentaire et la republication des avis sur Discord se règlent dans la [configuration](#sondage-de-satisfaction).

## Réponses types (onglet Réponses types)

Une **macro** met à un clic une réponse que le staff réécrit ticket après ticket, et lui attache ce qui suit d'habitude.

Le bouton **Nouvelle macro** demande :

* **Nom**, **Catégorie** et **Emoji**.
* **Contenu** : le texte envoyé, 2000 caractères maximum - la limite d'un message Discord. Les variables `{user}`, `{staff}`, `{ticket_id}`, `{ticket_type}` et `{server}` y sont remplacées.
* **Types de ticket concernés** et **Rôles autorisés** : vide, la macro vaut pour tous les types et tout le staff.
* **Mots-clés de suggestion** : les macros dont un mot-clé apparaît dans la demande remontent en tête du sélecteur.

### Actions attachées

Une macro peut faire plus qu'écrire :

* **Requalifier en** : changer le type du ticket.
* **Ajouter le rôle** et **Retirer le rôle**.
* **Déclencher l'enquête de satisfaction**.
* **Fermer le ticket** : appliquée en dernier, les autres ayant besoin d'un ticket encore ouvert.

### Envoi automatique

**Envoyer automatiquement à l'ouverture** poste la macro dès la création du ticket.

:::note[Ses actions ne s'appliquent pas]
Une macro envoyée à l'ouverture publie son texte mais n'applique pas ses actions : fermer ou requalifier un ticket qui vient de naître ferait plus de dégâts qu'autre chose.
:::

Dans le salon du ticket, le bouton **Macros** ouvre le sélecteur. Discord n'accepte que 25 entrées : les plus utilisées passent en tête.

## Liste noire (onglet Liste noire)

L'onglet **Liste noire des tickets** empêche certains membres d'ouvrir un ticket, sans passer par une sanction Discord.

* **Identifiant Discord** : l'ID du membre à bloquer.
* **Raison** : elle est **communiquée au membre** lorsqu'il tente d'ouvrir un ticket. Laissée vide, elle s'affiche comme *Aucune raison précisée*.
* **Durée (jours)** : vide, le blocage est **Définitif**.
* **Autoriser la réouverture de ses anciens tickets** : le membre ne peut plus ouvrir de ticket, mais peut encore demander à rouvrir un ticket déjà traité. L'entrée porte alors la mention **Réouverture autorisée**.

Chaque entrée indique qui l'a créée (*Ajouté par …*). **Retirer** lève le blocage.

## Configurer le module (onglet Configuration)

En haut de l'onglet, **Mise en route** crée ce qui manque - la catégorie des tickets, le salon du panneau et le salon des journaux - en gardant ce que vous avez déjà choisi. **Envoyer le message** publie le panneau d'ouverture dans son salon.

Les réglages sont regroupés en sections dépliables.

### Salons et rôles

* **Catégorie des tickets par défaut**, **Salon du panneau d'ouverture**, **Salon des journaux et transcriptions** et **Rôle staff support par défaut**.
* **Salon de relais des messages privés (mode MP)** : où arrivent les messages des tickets ouverts en message privé.
* **Autoriser la sur-revendication** : un membre du staff peut reprendre un ticket déjà revendiqué ; **Qui peut sur-revendiquer ?** l'ouvre à *Tout le staff* ou au *Grade supérieur ou égal*.
* **Prise en charge automatique** : dès qu'un membre du staff écrit dans un ticket ouvert, il en devient le référent.

Un salon ou un rôle introuvable sur le serveur est signalé : le module ne fonctionne pas tant qu'il pointe dessus.

### Apparence du message

Le panneau d'ouverture : **Titre**, **Description**, **Texte du bouton**, **Couleur**, images, auteur et pied de page. Le **Type d'interaction** affiche un bouton par type de ticket (**Boutons**) ou un **Menu déroulant** unique.

### Message d'accueil dans le ticket

Le message envoyé à l'ouverture du ticket, avec ses variables (`{type_label}`, `{user}`, `{staff_mention}`, `{reason}`, `{description}`) et sa **Couleur du message**.

### Validation et verrouillage

* **Verrouiller jusqu'à la prise en charge** : le salon reste visible par l'auteur et le staff, mais personne n'y écrit tant qu'un membre du staff ne l'a pas pris en charge.
* **Validation préalable du ticket** : la demande est transmise au staff, et le salon n'est créé qu'après acceptation. Le **Salon de validation** reçoit les cartes de décision (vide : le salon des journaux).

Chaque type de ticket peut suivre ces réglages ou décider autrement.

### Archivage

* **Catégorie d'archives** : les salons archivés y sont déplacés. Vide, le salon reste où il est et seules ses permissions changent.
* **L'auteur garde l'accès en lecture** : le membre continue de voir son ticket archivé sans pouvoir y écrire.

**Historique côté membre** ajoute sous le panneau un bouton **Mes anciens tickets** : chacun y voit ses tickets clos et leur transcription. **Réouverture par le membre** l'autorise à demander la réouverture d'un ticket clos (3 réouvertures au plus, avec des délais croissants) et **Suppression par le membre** à effacer l'un de ses anciens tickets ; les tickets verrouillés restent protégés.

### Inactivité

* **Activer les rappels** : un message automatique quand le créateur ne répond plus, après un **Délai (heures)**, avec le texte de votre choix.
* **Relancer le staff quand un membre attend** : si personne du staff n'a répondu au membre après le **Délai sans réponse (minutes)**, le bot mentionne la personne qui a pris le ticket, sinon le rôle staff. Une relance par attente, comptée dans les statistiques.

### Avertissement d'enregistrement

**Afficher l'avertissement avant chaque ticket** prévient le membre, avant la création de son ticket, que l'échange sera enregistré, transcrit et archivé. Il le lit dans un message que lui seul voit, et le ticket est créé une fois le **Délai de lecture** écoulé (5 à 30 secondes ; 10 à 15 laissent le temps de lire). Le **Texte de l'avertissement** est modifiable, et un aperçu le montre avec son compte à rebours.

### Objectifs de service

Deux délais à tenir, suivis dans la liste des tickets et dans la file **Hors délai** :

* **Première réponse (minutes)** ;
* **Résolution (heures)** : entre l'ouverture et la fermeture.

Vide, un délai n'a **Aucun objectif**.

### Quotas

Des limites d'ouverture côté membre, et un plafond de charge côté staff. Chaque quota s'active indépendamment, et un type de ticket peut ajuster le seuil.

| Quota | Ce qu'il limite |
| --- | --- |
| **Tickets ouverts simultanément** | Le nombre de tickets qu'un membre peut avoir en cours en même temps. |
| **Délai entre deux ouvertures** | Empêche d'enchaîner les tickets sans laisser le temps de répondre. |
| **Quota sur une période** | Plafonne le nombre d'ouvertures sur une fenêtre glissante (*Tickets maximum* sur *N heures*). |

La **Charge maximale par modérateur** compte les tickets pris en charge et encore ouverts ; au-delà, le staff est averti ou refusé.

### Sondage de satisfaction

* **Demander un commentaire** : après avoir noté, le membre peut ajouter un commentaire libre. La **Question posée** est modifiable, et le bouton disparaît du message privé passé le **Délai** (30 à 900 secondes). La note reste enregistrée même sans commentaire.
* **Salon des avis** : chaque avis y est republié - note, auteur, staff concerné et commentaire. Vide, rien n'est republié.
* **Masquer l'auteur de l'avis** : l'avis republié affiche *Membre anonyme*. Le dashboard, lui, continue d'afficher l'auteur.

### Types de tickets

Plusieurs choix de support (« Signaler un bug », « Question boutique »…). **Ajouter un type** puis réglez :

* le **Libellé du bouton / option**, l'**Emoji**, la **Couleur bouton** et la **Description de l'option** (pour le menu déroulant) ;
* le **Mode d'ouverture** : **Nouveau salon**, **Messages privés (MP)**, **Fil de discussion**, ou **Par défaut (global)** ;
* la **Catégorie cible** et un **Rôle staff spécifique** (vides : ceux par défaut) ;
* le **Verrouillage avant prise en charge** et la **Validation préalable**, propres au type ;
* l'**Anonymat du staff** en mode MP, et la création du ticket sur le [serveur du staff](/dashboard/cross-serveur/serveurs-staff/) pour un ticket interne (RH, plainte…).

**Activer le formulaire de questions pour ce type** pose jusqu'à **5 questions** avant l'ouverture. Sans question personnalisée, Kotbo pose *Sujet* et *Description*.

| Type de réponse | Où la question est posée |
| --- | --- |
| **Ligne courte** et **Paragraphe long** | Dans la fenêtre d'ouverture (modal Discord). |
| **Menu déroulant**, **Boutons radios** et **Fichier joint** | Dans le ticket, juste après sa création : le bot la pose lui-même. |

Les types à choix demandent leurs **Choix / options**, séparés par des virgules ; Discord n'affiche que les 5 premiers en boutons. **Champ obligatoire** force la réponse.

:::caution[Une question sans intitulé bloque l'enregistrement]
Discord refuserait le formulaire : Kotbo refuse d'enregistrer un type dont une question n'a pas d'intitulé.
:::
