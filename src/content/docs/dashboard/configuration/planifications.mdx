### Les types d'action

| Type | Effet |
| --- | --- |
| **Réinitialisation de salon (nuke)** | Clone le salon cible, supprime l'original, puis publie un message signalant la réinitialisation dans le nouveau salon. |
| **Sauvegarde complète du serveur** | Crée une [sauvegarde](/dashboard/configuration/sauvegardes/) automatiquement. Elle inclut membres, rôles, salons, emojis et stickers, mais **jamais les messages**. |
| **Export des données (journaux et profils)** | Produit un export des journaux et des profils. |
| **Message programmé** | Poste un message dans un salon, avec un embed facultatif. |

#### Message programmé

Le type **Message programmé** demande un **salon cible** et un **Message** - le texte posté dans le salon. Un **Embed (facultatif)** peut s'y ajouter, avec son titre, sa description, sa couleur et son image.

Deux garde-fous propres à un message qui se répète :

* **Autoriser les mentions**, refusé par défaut : sans cela, `@everyone`, `@here` et les mentions de rôle sont écrits mais ne notifient personne. Un message qui se répète ne doit pas pinger tout le serveur par accident.
* **Envoyer une seule fois** : la tâche se désactive juste après l'envoi. À cocher pour un message daté, dont l'expression cron se redéclencherait sinon l'année suivante.

Un message sans texte ni embed est refusé à l'enregistrement, plutôt qu'à l'heure dite où l'échec passerait inaperçu.

:::caution[Le salon cible est obligatoire]
Une réinitialisation de salon exige un **salon de destination**. Kotbo refuse d'enregistrer la tâche sans lui, et les salons de type fil ne sont pas pris en charge.
:::

:::danger[L'identifiant du salon change]
La réinitialisation ne vide pas le salon : elle en crée une copie et supprime l'original. Tout réglage extérieur qui désigne le salon par son identifiant (webhook, autre bot, configuration d'un module Kotbo) sera à refaire après chaque passage.
:::

### Les fréquences

* **Toutes les heures**
* **Chaque jour à minuit**
* **Chaque semaine** (dimanche à minuit)
* **Chaque mois** (le 1ᵉʳ à minuit)
* **Personnalisée**

L'expression cron suit le format Unix standard `minute heure jour mois jour-de-la-semaine`. Par exemple, `0 12 * * *` déclenche la tâche chaque midi.

## Gérer les planifications

Chaque carte rappelle la **fréquence**, le **salon cible** et le **dernier lancement** (ou *Jamais*).

| Bouton | Effet |
| --- | --- |
| **Lancer** | Exécute la tâche immédiatement, en arrière-plan, sans attendre la prochaine échéance. |
| **Modifier** | Rouvre le formulaire. |
| **Supprimer** | Retire définitivement la planification. |

Une planification peut aussi être **activée** ou **désactivée** sans être supprimée : pratique pour suspendre une tâche pendant un événement.

:::danger[Tester avant d'automatiser]
Utilisez **Lancer** une première fois à la main pour vérifier ce que fait réellement la tâche, en particulier pour une réinitialisation de salon, qui détruit l'historique.
:::
