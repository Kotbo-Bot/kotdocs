<p class="doc-lead">The <strong>Commands</strong> module restricts how Kotbo's slash commands can be used on your server. It is the essential tool for making sure your sensitive commands are not used by just anyone, just anywhere.</p>

:::tip[On the Discord side]
To learn how slash commands behave on Discord and how restrictions are applied live, read the [Discord command usage guide](/en/discord/configuration/commandes).
:::

:::note[Availability]
Execution rights are managed under **Settings → Commands** in the dashboard: [Open the Commands module ↗](https://dash.kotbo.fr/command-access).
Only members with administration rights, or roles allowed to configure the bot, can change these settings.
:::

---

## How the page is organised

The page is split into two main tabs, below the title:
* **Permissions**: the configuration interface where you define the access rules.
* **Structure**: the full list of Kotbo commands available on your server, with their description, their **parameters** and their **subcommands**. Every parameter is described by its type (*Text*, *Number*, *Member*, *Channel*, *Role*, *Attachment*…) and its status, **Required** or **Optional**.

Three figures sum the server up at the top of the page: **Commands**, **Restrictions** and **Disabled**.

A **search bar**, **categories** (*All*, *Moderation*, *Administration*, *Community*, *Economy*, *Fun*, *Utility*) and status filters (*With restrictions*, *No restrictions*, *Disabled*) help you find a command quickly.

---

## Turning a command off

As soon as a category or a search is chosen, **Enable all** and **Disable all** act on every command shown.

Every command card carries a switch. Turned off, it disables the command for the whole server.

:::caution[Administrators included]
*Command turned off for the whole server, administrators included. Re-enable it to configure access.* A disabled command carries the **Disabled** badge and its access settings are hidden.
:::

## Restricting a command

On an enabled command's card, the **Allowed roles** are set directly. The **Advanced restrictions** block expands for channels, blocked roles and members.

You can restrict a command against three criteria, which stack:

### 1. Roles
Determines which groups of users can run the command:
* **Allowed roles**: only members holding one of these roles can use the command.
* **Blocked roles**: members holding one of these roles are blocked, even if they have the default Discord rights.

*No role selected* means **default Discord behaviour**, based on the command's permissions. Administrators always keep access to enabled commands.

### 2. Channels
Determines the channels where the command is active:
* No channel: *Executable anywhere*.
* **Allowed channels**: *Restricted to configured channels*.
* **Blocked channels**: *Forbidden in configured channels*.

### 3. Members
Lets you target specific members by their Discord ID. Enter the **Discord ID**, then **Allow** or **Block**.

A **Rule summary** recalls in one line what the configuration produces: roles, channels and members allowed or blocked.

The **Quick actions** wipe things clean: **Clear channels**, **Clear roles**, **Clear members** or **Clear all**.

:::tip[Discord can do it too]
These permissions can also be managed directly in Discord, under **Server Settings → Integrations**.
:::

## Detecting and resolving conflicts

A configuration can sometimes end up with contradictory rules (for example if you add the `@Moderator` role to both the allowed roles and the blocked roles).

* **Conflict alert**: the dashboard detects these anomalies automatically and shows a red warning alert.
* **Resolve conflicts**: a button appears in the alert to clean up the configuration automatically, removing the conflicting duplicates in one click.

## Saving

:::caution[The save bar]
As on every configuration page, restrictions are not applied until you click **Save** in the green bar at the bottom of your screen.
:::
