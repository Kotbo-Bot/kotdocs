<p class="doc-lead">The <strong>Discord logs</strong> page records what happens on your server: deleted messages, joins, sanctions, voice moves, channel and role changes. It is both the history you consult and the place where you decide where each event is published.</p>

:::note[Where to find it]
The **Moderation → Logs** section: [Open the logs ↗](https://dash.kotbo.fr/logs).
Kotbo needs the **View audit log** permission and write access to the log channels.
:::

---

## Journal tab

Four counters summarise the period: **Total**, **Users**, **Unique** and **Sources**.

The **Discord events** table shows the **Time**, **Actor**, **Action**, **Channel**, **Category**, **Details** and **Type** columns.

* The **Quick search** field accepts an action, details, a module or a user.
* A counter shows how many events are displayed out of the total.
* The **Open case file** button goes straight to the moderation file of the member concerned.

If nothing shows up, Kotbo suggests changing your search filters.

---

## Audit & diff tab

This tab keeps every message, member, role or channel change with its **before** and **after** state.

* Filter by **type** (Message edited, Member updated, Role updated, Channel updated, Channel permissions), by **author** or by date range.
* The **View changes** button shows the before/after comparison, with the number of additions and removals. For permissions, Kotbo distinguishes **Allowed**, **Denied** and **Back to inherited**.

Under **Audit configuration**, you can enable before/after state capture, choose what is captured (messages, members, roles, channels), exclude channels, and set a **Retention (days)** value (`0` keeps events indefinitely).

## Configuration tab

:::note[Restricted tab]
This tab only appears for members allowed to manage server settings. Moderators see only **Journal** and **Server changes**.
:::

### Logging

* **Enable global audit**: the main logging switch.
* **Activity tracking**: records the actions performed.
* **Channel notifs**: publishes alerts in the log channel.
* **DM notifications**: sends alerts to staff by direct message.

### Default channel

Set the **general log channel**, used for every event that has no specific channel of its own.

### Excluded channels

The **Excluded channels** field takes channels out of logging: no message event (deletion, edit, purge) and no voice event (join, leave, move) coming from those channels will be logged, message content recording included. Threads follow their parent channel's exclusion.

:::note[Collection carries on]
It is the logging that stops, not the collection: the statistics and the members' records are unchanged.
:::

### Per-event configuration

You can enable each event separately and give it its own **Destination channel**. Events are grouped by category:

| Category | Events |
| --- | --- |
| **Messages** | Message deleted, Message edited, Bulk deletion |
| **Members** | Member joined, Member left, Roles updated, Member timeout |
| **Moderation** | Kick, Ban, Unban, Timeout (Audit) |
| **Voice** | Voice connect, Voice disconnect, Channel switch, **Voice panel** (every action taken from a temporary voice channel panel: who, what, on which channel) |
| **Channels & Roles** | Channels (create, update, delete), Roles (create, update, delete) |

Each category has a **Manage this category's alerts** shortcut to turn the whole group on or off at once.

:::tip[Split your journals]
Send moderation events to a staff-only channel and keep the default channel for the rest. Your moderators will find sanctions much faster without the noise of voice connections.
:::

Remember to save: Kotbo confirms with an *Event configurations saved successfully* message.
